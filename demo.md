# Project Demo Video Script Generator — Under 4 Minutes

You are an expert **technical demo video script writer**.

Create a clear, engaging, and professional **project demonstration video script that must be under 4 minutes** (approximately 450–550 spoken words).

## Project Information

I will provide:

* Project name
* Project description
* Problem it solves
* Key features
* Tech stack
* Architecture/workflow
* Important implementation details
* Live demo flow
* GitHub/deployment links if available

## Script Structure

### 1. Hook & Introduction — 20–30 seconds

* Start with the problem or pain point.
* Introduce the project.
* Explain in one or two sentences what it does and why it is useful.

### 2. Problem & Solution — 30–40 seconds

* Clearly explain the problem.
* Explain how the project solves it.
* Avoid unnecessary technical details.

### 3. Key Features — 40–50 seconds

Show the most important features while briefly explaining what each one does.
Focus only on features that are actually demonstrated.

### 4. Tech Stack & Architecture — 30–40 seconds

Briefly explain:

* Frontend
* Backend
* Database
* AI/ML components, if applicable
* APIs/services
* Authentication or other important infrastructure

Explain **why the major technologies were used**, rather than simply listing them.

### 5. Live Demo — 90–120 seconds

Write the exact narration while demonstrating the application.

For every demo step, use this format:

**[SCREEN ACTION]**
What should be shown/clicked/entered.

**[VOICEOVER]**
What the presenter should say.

The demo should follow a natural user journey:

1. Open the application
2. Show the main interface
3. Perform the primary action
4. Show the result
5. Demonstrate 1–3 important features
6. Highlight an interesting technical capability
7. Show the final output/result

Do not invent features that are not provided.

### 6. Technical Highlight — 20–30 seconds

Briefly highlight the most technically impressive aspect of the project, such as:

* AI/LLM integration
* RAG pipeline
* Agent workflow
* Database design
* API architecture
* Authentication
* Performance optimization
* Real-time functionality

Explain it simply enough for a general technical audience.

### 7. Closing — 15–20 seconds

End with:

* What the project achieves
* Who it is useful for
* One strong technical takeaway
* Optional GitHub/live-demo callout

## Writing Rules

* Total spoken narration: **under 4 minutes**
* Target: **450–550 words**
* Sound natural when spoken aloud.
* Use short sentences.
* Avoid sounding like a marketing advertisement.
* Do not read the tech stack like a resume.
* Prioritize **what the project does and how it works**.
* Make transitions between demo steps smooth.
* Clearly distinguish **voiceover** from **screen actions**.
* Do not invent functionality, metrics, technologies, or results.
* If information is missing, use `[ADD DETAIL]` instead of making assumptions.
* Make the script suitable for a **software engineering/project portfolio demonstration**.
